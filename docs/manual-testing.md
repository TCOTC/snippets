# 代码片段管理器（snippets）手工测试用例集

本文件针对 `data/plugins/snippets` 插件（思源笔记「代码片段管理器」）整理**手工测试用例**。用例按功能域分组，编号 `MT-xx`，每项含前置条件、操作步骤与预期结果。预期结果以当前源码（`src/`，2026-09-05 版）的行为契约为准——如果实测与预期不符，请按文档末尾的模板反馈，并尽量标注涉及的源码模块（见每节开头说明）。

> 提示：本项目已有大量单元测试（`pnpm test`，覆盖 domain/services/UI 纯逻辑）。手工测试重点验证**浏览器真实环境下的 DOM 交互、思源内核 API 联动、多窗口/多会话协同**等单测无法覆盖的部分。

---

## 0. 测试前准备

### 0.1 环境
- 思源笔记桌面端（建议不低于 `plugin.json` 的 `minAppVersion`，当前 3.8.3-alpha.1），Windows / macOS / Linux 均可（文档以桌面端为主，移动端专项见第 15 节）。
- 安装并启用本插件（本地开发时：修改 `src/` 后需执行 `pnpm build`（或 `pnpm dev`）重新生成 `dist/index.js`，再到思源中重新加载插件）。
- 建议准备 **同内核多窗口** 环境用于跨窗口测试：
  - 窗口 A：思源桌面端主窗口；
  - 窗口 B：同内核再开一个前端（桌面端「窗口 - 新建窗口」，或浏览器访问同端口的 `http://127.0.0.1:<端口>/stage/build/app/`）。
- 如测「发布站点」相关（可选），需准备思源发布服务（`设置 - 发布` 开启）与发布会话页面。

### 0.2 打开入口速查
| 操作 | 桌面端 | 移动端 |
|---|---|---|
| 打开管理菜单 | 点击顶栏插件按钮（默认右侧） | 点击右侧栏插件按钮/选项 |
| 打开插件设置 | 管理菜单顶部齿轮按钮；或思源 `设置 - 资源 - 插件 - 代码片段管理器 - 设置` | 同左 |
| 打开编辑对话框 | 管理菜单片段项「编辑」按钮 | 同左 |
| 打开思源原生代码片段窗口 | 插件设置 -「打开窗口」按钮 | 不提供 |

### 0.3 准备测试片段
建议按用例需要准备若干 CSS / JS 片段，例如：
- CSS：`body { --test-color: red; }`（可观察：把某元素变红便于验证生效/移除）
- JS：`console.log("hello snippets");`（可在开发者工具观察输出，验证注入与重载）
- 片段标题留空 / 超长 / 含 `<script>` 等 HTML 特殊字符（验证防 XSS 与回退标题）
- 无效 JS（如 `var = ;`，验证拒绝与提示）

### 0.4 测试期间建议打开开发者工具 Console
插件支持 `设置 - 在开发者工具中输出插件日志`（默认关）。排查问题时开启后，Console 会打印菜单打开、元素注入、跨窗口广播等日志，便于定位。

## 1. 加载与基础冒烟（模块：`src/index.ts`）

### MT-001 插件加载
- 前置：已启用插件。
- 步骤：重新加载思源界面（或重启），查看 Console。
- 预期：Console 出现 `<显示名> plugin onloaded`（显示名即「代码片段管理器」/ Code Snippets Manager，随语言）；无红色报错；顶栏出现插件按钮（桌面端）。

### MT-002 插件禁用清理
- 前置：至少打开一个编辑对话框、菜单、文件监听（若有），并制造若干插件监听器。
- 步骤：`设置 - 资源 - 插件` 关闭「代码片段管理器」。
- 预期：
  - 所有插件对话框立即关闭（含编辑对话框、确认框、设置框）；
  - 管理菜单消失，顶栏按钮变灰/移除（由思源宿主处理）；
  - 编辑对话框期间注入的 `.cm-content` 全局样式被移除（页面样式恢复）；
  - 文件监听停止（如开启了监听，轮询定时器停止）；
  - 无残留异常日志。
  - 已生效的内核代码片段（style/script）不受影响（由思源内核自身渲染管理）。

### MT-003 重新启用插件
- 步骤：在插件管理里重新启用。
- 预期：插件正常加载，顶栏按钮恢复；打开菜单列表内容与内核一致（自动自拉）。

### MT-004 插件卸载
- 前置：桌面端已配置过若干非默认设置（便于确认配置删除）。
- 步骤：`设置 - 资源 - 插件 - 卸载`，然后重新安装启用插件。
- 预期：
  - 卸载时 Console 依次出现 `unloaded` 与 `uninstalled` 日志；
  - 工作空间 `data/storage/petal/snippets/plugin-config.json` 被删除；
  - 重新安装后所有设置回到默认值（默认值清单见 MT-121）。

### MT-005 发布页会话不加载管理 UI（可选，需发布服务）
- 前置：开启思源发布服务并发布了工作空间。
- 步骤：浏览器打开发布站点页面（会话角色为发布站）。
- 预期：
  - 插件随发布页加载（`disabledInPublish` 为 false）但不显示任何管理入口：无顶栏按钮、无菜单、无文件监听、快捷键无效；
  - 发布页内容片段按各片段 `disabledInPublish` 元数据过滤注入（原生发布渲染行为）。

## 2. 管理菜单（模块：`src/ui/menu.ts`）

### MT-010 打开与再次点击关闭
- 前置：桌面端。
- 步骤：点击顶栏插件按钮。
- 预期：在按钮下方弹出菜单（宽 `min(400px, 90vw)`），菜单含：顶部选项卡区（CSS / JS 计数 + 搜索 + 设置 + 重载 + 新建 + 全局开关）、搜索输入框（可隐藏）、片段列表容器；按钮呈激活态（高亮、无 tooltip）。再次点击同一按钮 → 菜单关闭，按钮取消激活。

### MT-011 菜单计数
- 前置：内核中存在 N 个 CSS、M 个 JS 片段。
- 步骤：打开菜单查看选项卡。
- 预期：CSS 标签显示 N、JS 标签显示 M；任一计数超过 99 时显示 `99+`；菜单打开期间在别处增删片段并重新自拉后计数同步刷新。

### MT-012 打开时列表自拉刷新
- 前置：插件运行中，且内核片段被外部修改（例如另一窗口/另一设备新增了片段，或手工编辑了 `data/snippets/conf.json` 后触发重载）。
- 步骤：打开菜单。
- 预期：列表内容与内核权威数据一致（打开菜单时总先自拉 `/api/snippet/getSnippet`）；若自拉失败弹「获取代码片段列表失败」错误且菜单不展示（已创建即关闭）。

### MT-013 CSS / JS 选项卡切换
- 前置：存在 CSS 与 JS 片段各若干。
- 步骤：点击「CSS」/「JS」标签。
- 预期：列表仅显示对应类型片段；选项卡滑条跟随；「+」按钮提示文案随类型变为「添加 CSS / JS」；全局开关状态反映该类型（思源 `设置 - 外观 - 代码片段` 中 CSS/JS 的启用态）；CSS 片段恒排在 JS 片段之前（分区不混排）。
- 记忆点：切换后再次打开菜单记住上次类型；插件重载后回退到配置「默认标签页」值。

### MT-014 顶部按钮：设置
- 步骤：菜单打开时点击齿轮按钮。
- 预期：打开插件设置对话框（标题为插件显示名），菜单仍位于其下层；设置项与第 8 节清单一致。

### MT-015 顶部按钮：新建（+）
- 步骤：菜单打开时点击「+」。
- 预期：当前类型（CSS 或 JS）弹出新建编辑对话框，标题输入框聚焦，按钮文案为「新建」；若片段由 `新建代码片段时默认启用=true`，保存后立即启用并生效。

### MT-016 某类型无片段时的「添加第一个」入口
- 前置：当前类型（如 CSS）没有任何片段。
- 步骤：打开菜单（CSS 页）。
- 预期：列表区显示「添加第一个 CSS 代码片段」项（居中样式）；点击后打开新建对话框，类型为 CSS。
- 反向验证：该类型已有 ≥1 个片段时入口**不显示**；JS 类型页同理显示「添加第一个 JS 代码片段」。

### MT-017 模态对话框存在时顶栏按钮不响应
- 前置：存在打开中的插件**模态**对话框（例如删除确认框、设置对话框未关闭）。
- 步骤：点击顶栏插件按钮（或快捷键）。
- 预期：菜单不打开。
- 补充：桌面端若打开的仅是**非模态**编辑对话框（多编辑器开启时），顶栏按钮仍可打开菜单（此时可观察编辑按钮联动高亮等行为）。

### MT-018 片段项悬停提示与安全名称
- 前置：一个片段标题为空、一个标题含 HTML（如 `<b>xx</b>`）、一个标题超长。
- 步骤：打开菜单观察。
- 预期：标题为空的片段显示其**内容前 200 字符**（snippetTitle 回退）；标题与内容均为空的片段显示灰色占位「空代码片段」（`placeholder` 样式）；含 HTML 的标题按纯文本渲染（`textContent` 写入，不破坏菜单 DOM、不产生 HTML 注入）；超长标题不撑破菜单（名称区域可横向滚动查看）。

### MT-019 片段项操作按钮显隐与悬停
- 前置：配置三个「显示按钮」开关（默认：删除开、编辑开、副本关）。
- 步骤：打开菜单观察片段行（鼠标移入/移出该行）。
- 预期：
  - 配置为开的按钮**悬停该行时出现**、移出后隐藏（桌面端交互，触屏设备常显）；
  - 配置为关的按钮即使悬停也不出现（未生成）；
  - 编辑对话框打开期间对应行的「编辑」按钮呈高亮常显（不受悬停控制）；
  - 配置在菜单开着时经设置热改 → 按钮显隐即时变化（见 MT-123）。

### MT-020 点击片段行的动作按钮不改变开关
- 步骤：悬停片段行，点击「编辑 / 复制 / 删除」按钮。
- 预期：仅执行对应动作，该片段启用开关状态不变。

### MT-021 编辑按钮联动高亮
- 前置：桌面端，菜单打开。
- 步骤：点击片段「编辑」打开编辑对话框。
- 预期：菜单内该片段行的编辑按钮高亮（背景色）；菜单**不会**关闭；关闭编辑对话框后高亮消失；编辑对话框被置顶激活（重复打开同一片段只激活不重建）。

## 3. 片段 CRUD（新建 / 保存 / 更新 / 复制 / 删除；模块：`src/services/snippet-manager.ts`、`src/domain/snippet-store.ts`）

### MT-030 新建 CSS 并保存
- 步骤：菜单「+」新建 CSS → 输入标题与 CSS 内容 → 点击「新建」。
- 预期：
  - 对话框关闭；菜单计数 +1；菜单列表顶部出现新片段（类型 = 菜单当前类型，如从 CSS 页新建则为 CSS）；
  - 若「新建时默认启用」开启且 CSS 全局开启，样式立即生效（`<style id="snippetCSS…">` 注入 head）；
  - 思源 `设置 - 外观 - 代码片段` 中出现该片段（落库成功，`data/snippets/conf.json` 已更新）。

### MT-031 更新既有片段（仅改名）
- 前置：片段已启用且其 CSS 生效中。
- 步骤：编辑 → 仅修改标题 → 保存。
- 预期：菜单项名称更新；**注入元素不重建**（样式无需重新注入）；无「重载界面」提示；落库成功。

### MT-032 更新既有片段（内容变更，CSS）
- 步骤：编辑 → 修改 CSS 内容 → 保存。
- 预期：菜单项名称不变；注入 style 内容更新，新样式立即生效（元素整体重建）；落库成功。

### MT-033 更新既有片段（内容变更，JS）
- 前置：JS 全局开启且该片段启用、已注入且旧代码有效。
- 步骤：编辑 → 修改 JS 内容 → 保存。
- 预期：
  - 弹通知「修改 JS 代码片段后需重新加载界面…」（若通知开关开启，含「不再提示」按钮）；菜单顶部重载按钮呼吸（若菜单开）；
  - 若「JS 修改后自动重新加载界面」开启且无其他编辑对话框打开 → 保存后界面自动重载（脚本新代码生效）；
  - 若自动重载关闭 → 界面不重载，需手动点击重载按钮/关闭菜单触发（见 MT-094），脚本旧代码仍运行直至重载。

### MT-034 保存按钮文案流转（新建 → 已存在）
- 步骤：打开**已存在**片段的编辑对话框（菜单编辑按钮路径）。
- 预期：按钮文案为「保存」且显示删除按钮；而**新建**对话框按钮文案为「新建」且删除按钮隐藏。新建保存成功后（若菜单还开着该对话框对应行），按钮文案变为「保存」、删除按钮出现。

### MT-035 复制片段
- 前置：菜单片段行显示副本按钮（配置开启）或直接验证「显示副本按钮」默认关闭的前提。
- 步骤：开启 `管理菜单显示创建副本按钮` → 打开菜单 → 点击某片段行「复制」。
- 预期：
  - 该片段上方插入副本菜单项，标题为「<原标题> (副本 <日期时间>)」，内容/启用/发布开关状态与原片段一致，ID 为新生成；
  - 副本若启用且类型全局开启 → 立即注入生效（CSS 可观察样式叠加，JS 会在 console 多执行一次）；
  - 菜单计数 +1；落库成功；原片段不受影响。
- 注意：副本按钮默认关闭，未开启时菜单行不显示该按钮。

### MT-036 从菜单删除片段
- 前置：删除确认对话框默认聚焦红色「删除」按钮。
- 步骤：菜单点击片段行「删除」→ 确认框（标题「⚠️ 删除操作确认」，正文含片段名加粗）→ 按 Enter 或点击「删除」。
- 预期：片段从菜单消失、计数 -1、注入元素移除（CSS 效果消失）、内核列表与 conf.json 同步删除。取消（Esc / 点击「取消」）→ 不删除。
- 扩展（JS 片段）：删除**已启用且旧代码有效**的 JS 片段时弹「修改 JS 代码片段后…」通知；若开启自动重载且无打开编辑对话框，关闭菜单后自动重载界面。

### MT-037 从编辑对话框删除
- 步骤：打开既有片段编辑对话框 → 点标题行右侧垃圾桶 → 确认框出现 → 确认删除。
- 预期：片段删除（同 MT-036 效果），编辑对话框随之关闭；若删除的是**当前正在实时预览的 CSS 片段**，对话框关闭后预览样式随之移除。

### MT-039 保存后对话框先关闭再生效
- 步骤：编辑片段并保存（含内容变化）。
- 预期：点击保存瞬间对话框即关闭（不等落库完成）；随后样式/脚本生效；若落库失败弹「保存代码片段列表失败 […]」。

## 4. 编辑对话框与 CodeMirror（模块：`src/ui/snippets-dialog.ts`、`src/ui/editor-manager.ts`）

### MT-050 打开编辑对话框
- 前置：桌面端。
- 步骤：菜单片段行点击「编辑」。
- 预期：出现对话框（宽 70vw、高 80vh），含：标题输入框、删除按钮、发布开关、启用开关、CodeMirror 编辑区、底部按钮（取消 / [预览] / 保存或新建）；标题输入框聚焦；编辑区显示语法高亮、行号、内容正确。

### MT-051 多编辑器共存（桌面端）
- 前置：`同时打开多个代码片段编辑器` 默认开启。
- 步骤：依次打开 A、B 两个不同片段的编辑对话框。
- 预期：两个对话框可同时存在，均为非模态（点击可切换置顶），点击其中一个即置顶（zIndex 提升）；标题栏可拖动。若仅打开一个对话框，其背景无 scrim（非模态）。
- 若配置改为关闭（`multipleSnippetEditors=false`）：只能打开一个，第二段打开请求被忽略（有模态对话框已打开时不打开新的）。

### MT-052 标题输入框焦点流转
- 步骤：编辑对话框打开（焦点在标题框）→ 按 Enter / Tab。
- 预期：焦点跳入代码编辑区；标题框无法输入换行；在标题框输入任意文本不触发对话框其它动作。

### MT-053 Ctrl+Enter 保存
- 步骤：在编辑区按 `Ctrl+Enter`。
- 预期：执行保存（同点击「保存/新建」按钮），不插入换行。

### MT-054 编辑区按键隔离（issue #19）
- 步骤：在编辑区内分别按 `Ctrl+F`、`Ctrl+B`、`Ctrl+I`、`Ctrl+P`、`Ctrl+Shift+F`、普通字母键。
- 预期：
  - `Ctrl+F` 仅打开 CodeMirror 内置搜索面板（可替换、可关闭），**不会**呼出思源全局搜索/其它原生快捷键；
  - 其它组合键不触发思源原生操作（不弹菜单、不切换文档等）；普通输入、Backspace、回车正常；
  - 若思源原生设置中为插件命令绑定了快捷键（如 openSnippetsManager），在编辑区内按下不应触发。

### MT-055 编辑器基础能力

## 10. 导入导出（模块：`src/services/import-export.ts`）

### MT-140 导出 JSON
- 前置：内核有若干片段。
- 步骤：设置 →「导出」→ 系统弹出另存为/下载。
- 预期：下载文件名为「代码片段 <yyyy-MM-dd HH-mm-ss>.json.zip」（导出为 zip 压缩包，内含代码片段 JSON 数据，结构与 `data/snippets/conf.json` 的片段数据一致）；生成的临时文件位于工作空间 `temp/export/`（重命名去除随机前缀）；可直接用该 zip 走导入流程验证往返（见 MT-144）。

### MT-141 导入追加（json）
- 前置：准备一份合法 JSON 文件（数组，元素含 name/content/type/enabled；结构同 `data/snippets/conf.json` 的 snippets 数组）。
- 步骤：设置 →「导入并追加」→ 选择文件。
- 预期：弹成功通知「代码片段导入并追加成功」；导入片段位于现有列表**之前**（重开管理菜单可见排在最前）；原片段保留；计数增加；落库成功。
- 若导入文件内 ID 与现有片段冲突 → 自动生成新 ID（不覆盖现有片段）。

### MT-142 导入覆盖（json）
- 前置：现有片段若干。
- 步骤：设置 →「导入并覆盖」→ 选择文件。
- 预期：先在工作空间 `temp/plugin-snippets/snippets_backup_<时间戳>.json` 写入当前全部片段备份；然后现有片段**全部被导入文件替换**；弹「导入并覆盖成功」。
- 还原验证：可用该备份文件以「导入并覆盖」还原现场。

### MT-143 导入格式校验
- 步骤：依次导入 ① 空文件 ② 非 JSON 文本（如 `hello`）③ 非数组 JSON（如 `{"a":1}`）④ 数组但元素缺字段/类型错误（如缺 name、type 非 css/js、enabled 非布尔）。
- 预期：错误提示分别对应「导入文件内容为空」（①）「文件内容不是有效的 JSON 格式，请检查文件内容」（②）「导入的文件格式无效，请选择正确的 JSON 文件」（③④，结构校验失败统一提示）；任何情况下现有片段不被改动。

### MT-144 导入 zip
- 前置：把导出的 zip（或任意含 json 的 zip，允许内嵌一层文件夹）放到本地。
- 步骤：设置 →「导入并追加」→ 选择该 zip。
- 预期：自动解压并递归找到其中合法 JSON 文件后导入；找不到可用 JSON 弹「未在压缩包中找到可用的 JSON 文件」；zip 内 JSON 非数组格式时报格式错误；导入过程使用 `temp/export/import-*` 临时目录（完成后可手动检查清理或忽略）。

### MT-145 导入后的数据与菜单状态
- 步骤：导入一组包含 JS 片段的文件。
- 预期：
  - 数据层立即更新：重新打开菜单（或再次自拉）可见导入片段，JS/CSS 计数正确；
  - 若导入时菜单正打开：计数即时刷新，但片段项 DOM 按当前实现**不会自动重绘**——关闭菜单重开后显示完整新列表（若实测自动重绘了属实现已变化，记录即可）；
  - 菜单类型总开关状态（enabledCSS/enabledJS 镜像）不因导入改变。
  - 元素注入时效见探索项 E-6。

## 11. 本地文件监听（模块：`src/services/file-watch.ts`）

### MT-150 启动监听基础
- 前置：工作空间建目录 `data/snippets`（默认路径）并放入 `a.css`、`b.js` 文件；若目录已有 conf.json 不影响。
- 步骤：设置中把 `本地文件监听` 从「禁用」改为「启用」，保存。
- 预期：
  - 立即加载目录内 `.css/.js` 文件：CSS 生效（`<style id="snippetCssJcsmWatch…" data-file-path=…>` 注入 head），有效 JS 注入执行（`console` 可见输出）；
  - 无效 JS 文件被跳过且不注入（仅日志）；
  - 配置改回「禁用文件监听」保存 → 停止轮询并移除已注入的 watch 元素（样式/脚本消失）；JS 移除场景弹重载提示 + 自动重载（若满足条件）。

### MT-151 仅启动加载一次（loadOnly）
- 步骤：设置 `本地文件监听 = 启动时加载一次`，保存后**新增/修改**目录内文件。
- 预期：只在保存设置时加载一次现有文件；之后的文件变化不被应用（无轮询）；重启思源后仍会启动时加载一次。

### MT-152 轮询新增文件
- 前置：监听已启用（间隔默认 5 秒）。
- 步骤：向目录放入 `new.css`（内容可观察）并保存。
- 预期：一个轮询周期内 new.css 自动生效（样式注入），无需手动操作。

### MT-153 轮询修改文件（CSS）
- 步骤：编辑监听目录内某 css 文件内容并保存。
- 预期：下个周期样式自动更新为最新内容（旧元素先移除再重建，不重复堆积）。

### MT-154 轮询修改文件（JS，启用自动重载）
- 前置：`自动重新加载界面` 开启。
- 步骤：修改监听目录内**已注入**的 js 文件并保存。
- 预期：下个周期弹「修改 JS 代码片段后…」通知；无打开编辑对话框时界面自动重载使新脚本执行；有打开编辑对话框时不重载（避免丢内容），关闭全部编辑对话框后触发自动重载。
- 若 js 文件为新加入（此前未注入）→ 直接执行，不弹重载提示。

### MT-155 轮询修改文件（JS，关闭自动重载）
- 前置：`自动重新加载界面` 关闭。
- 步骤：修改已注入 js 文件并保存。
- 预期：通知弹出（若开关开）且不自动重载；手动点重载后生效（新脚本执行）；文件状态已跟踪（再次修改不重复累积）。

### MT-156 轮询删除文件
- 步骤：删除监听目录内某 css / js 文件。
- 预期：下个周期对应注入元素被移除（CSS 效果消失；JS 移除弹重载提示并按自动重载规则处理）；文件状态表同步清理（删除后重新创建同名文件会被当新增重新注入，不残留旧元素——避免重复 ID/元素堆积）。

### MT-157 修改监听路径
- 步骤：设置中把路径改为另一相对路径（含有效 css/js 文件）并保存。
- 预期：旧路径全部 watch 元素移除（JS 弹提示逻辑同 MT-156），新路径文件立即加载生效；文件状态表重置。

### MT-158 无效路径
- 步骤：把监听路径改为不存在目录（如 `data/nonexistent-folder`）保存；以及改为**绝对路径**（如 `C:\xxx`）保存。
- 预期：弹错误「无效的文件夹路径: …」（相对不存在）或「不支持监听绝对路径: …」（绝对路径），监听自动停止（可核对设置重新启用后正常）。错误为长驻提示（timeout 0）。

### MT-159 修改轮询间隔
- 步骤：监听开启时把间隔改为 1 秒 / 30 秒并保存。
- 预期：定时器按新间隔重置（可对照修改文件到生效的耗时）；输入框自带 1-300 的数值约束；保存时若解析为 0/空/非数字，回退为当前配置值（默认 5）。

### MT-160 监听与片段管理并存
- 步骤：监听目录内文件与内核 `data/snippets/conf.json` 管理的片段并存，观察交互。
- 预期：文件监听元素使用 `snippetCssJcsmWatch…/snippetJsJcsmWatch…` 专属前缀，与插件普通片段元素（`snippetCSS…`）互不冲突、互不影响增删。

## 12. 跨窗口同步（模块：`src/services/sync.ts`、`src/services/snippet-manager.ts`；双窗口 A/B）

前置（以下用例均在双窗口 A、B 同时启用插件、同一内核）：先在 B 打开管理菜单并切到相关类型页，便于观察即时 UI 更新。

### MT-170 广播通道连通
- 步骤：确认 A/B 均加载插件后查看 Console。
- 预期：两个窗口各有一次 `Broadcast Channel has been initialized, Window ID: snippets-plugin-sync-…`；断网/关闭某窗口不干扰另一窗口。

### MT-171 A 新建保存 → B 同步
- 步骤：A 新建一个 CSS 片段并保存（启用）。
- 预期：B 无需刷新：菜单顶部出现新片段项、计数 +1、样式立即注入生效（`.jcsm-` 菜单与 style 元素均可见）；B 不做重复落库（内核数据只一份）。

### MT-172 A 更新内容 → B 同步
- 步骤：A 修改片段内容保存（CSS 内容变化 / JS 内容变化）。
- 预期：B 注入元素内容同步更新（CSS 生效；JS 会弹「重载界面」提示并按 B 自己的自动重载配置处理）；B 菜单标题同步（仅改名时菜单名更新、元素不重建、不弹 JS 提示）。

### MT-173 A 行内开关 → B 同步
- 步骤：A 菜单切换片段启用开关。
- 预期：B 菜单对应行开关状态同步、注入元素同步增删；B 无重复弹窗/异常日志。

### MT-174 A 发布开关 → B 同步
- 步骤：A 拨动片段「发布开关」。
- 预期：B 菜单行发布开关勾选同步变化（勾选语义 = 允许发布）；元素不变化。

### MT-175 A 全局开关 → B 同步
- 步骤：A 关闭 CSS 全局开关。
- 预期：B 的 CSS 全部元素移除（该类型启用片段）；B 菜单全局开关同步为关。重新开启同理恢复。
- 风险提示（已知探索点）：思源内核 `setSnippet` 会向所有实例广播并全量重渲注入元素，插件再自带一轮 remote 同步，极端场景可能出现 JS 双执行/元素重建抖动——若观察到 JS 重复执行或元素闪烁，请记录复现步骤上报。

### MT-176 A 删除 → B 同步
- 步骤：A 删除片段。
- 预期：B 菜单项消失、计数 -1、注入元素移除（若 A 正在实时预览该片段则不触发 B 移除——预览状态由 A 接管，见 MT-180）。

### MT-177 A 复制 → B 同步
- 步骤：A 复制片段。
- 预期：B 菜单在原件上方出现副本项，副本注入生效；B 计数同步。

### MT-178 A 拖拽排序 → B 同步
- 步骤：A 在自定义排序下拖拽调整顺序。
- 预期：B 菜单片段顺序实时重排（B 重新自拉 + 重绘列表）；内核顺序一致。

### MT-179 A CSS 实时预览 → B 实时跟随
- 步骤：A 打开 CSS 片段编辑对话框并输入未保存样式（实时预览）。
- 预期：B 界面样式随 A 键入实时变化（跨窗口预览，广播携带编辑中 CSS 文本——本场景是唯一允许携带原文的豁免）；A 取消退出预览 → B 恢复该片段已保存样式（A 未保存则 B 恢复原样）。
- 若 A 实时预览中直接关闭思源/切换设备离线，B 下一次自拉/重载后回到已保存态。

### MT-180 A 预览中删除保护
- 步骤：A 打开 CSS 片段实时预览对话框（编辑中未保存）→ B 删除该片段。
- 预期：A 侧预览样式不被 B 删除动作误删（A 继续编辑）；A 关闭对话框后按已删除状态清理自身预览元素；A/B 最终均无残留注入元素（若发现残留或报错请记录，属已知复杂场景）。
- 反向：A 无预览对话框时 B 删除 → A 正常移除元素并更新列表。

### MT-181 消息协议完整性（行为抽查）
- 步骤：在 A 完成一次「新建 JS 并保存」→「改内容保存」→「禁用」→「删除」全流程，观察 B Console。
- 预期：B 依次收到并正确处理 `snippet_save`（无 content 字段，仅 ID+isCopy）`snippet_toggle`/`snippet_delete` 等消息；消息体不含片段原文（敏感约束）；未注册消息类型（人工在 Console 注入测试消息 `{type:"unknown", windowId:"x"}`）仅打 warn，不抛错不崩溃。

### MT-182 配置跨窗口热同步
- 步骤：B 打开插件设置修改「管理菜单显示编辑按钮=关」「顶栏按钮位置=左」并保存 → 观察 A。
- 预期：A **无需重载插件**即自动应用（`onDataChanged` → 热应用）：菜单按钮显隐、顶栏按钮位置即时变化；A 打开设置可见新值。

## 13. 键盘操作与全局键盘协调（模块：`src/ui/menu.ts` globalKeyDownHandler、`src/utils.ts` 键盘登记工具）

### MT-190 菜单方向键导航
- 前置：菜单打开（焦点在 body）。
- 步骤：按 `↓` / `↑` 若干次，按 `Enter`。
- 预期：高亮在当前类型**可见**片段间上下循环（菜单刚打开时已默认选中首个可见项，再按 ↓ 到下一项，越界循环）；当前类型无片段时选中「添加第一个 XX」项，Enter = 新建（占位项 data-type=new）；Enter 在片段项上 = 切换其启用开关；Esc = 关闭菜单。
- 菜单中搜索框聚焦期间按键不参与菜单导航（焦点不在 body）：方向键移动输入光标、Enter 不触发开关（避免与输入冲突）；Esc 交由思源原生处理关闭菜单（与原生菜单表现一致）。

### MT-191 菜单左右键切换类型
- 步骤：菜单打开按 `←`/`→`。
- 预期：CSS ↔ JS 选项卡来回切换，列表与全局开关随之切换（同 MT-013 点击标签效果）。

### MT-192 Esc 优先级仲裁
- 场景 1：仅菜单打开，焦点在 body → 按 Esc → 菜单关闭。
- 场景 2：桌面端菜单 + 非模态编辑对话框同开，**焦点位于编辑区/标题框** → 按 Esc → 走编辑对话框取消流程（有未保存变更则弹确认框；确认框上再按 Esc = 回到继续编辑，菜单保持在下层不关闭）。
- 场景 3：模态对话框（删除确认/设置）打开 → 按 Esc → 仅该模态框响应（取消/关闭），下层菜单不响应。
- 补充：焦点在 body（菜单与对话框都不持有焦点）时按 Esc，若窗口内无任何模态框，则菜单不处理、最高非模态编辑对话框也不处理（无动作）属已知边界，可记录表现后反馈。

### MT-193 模态期间禁止菜单动作
- 步骤：删除确认框打开时按 `↓`、`Enter`（焦点在 body 上时）。
- 预期：按键路由到确认框逻辑（Enter=确认删除，Esc=取消）；不操作下层菜单、不关闭菜单。

### MT-194 快捷键命令
- 前置：`设置 - 快捷键` 中为插件命令「打开代码片段管理器」「重新加载界面」绑定快捷键（见 MT-127 跳转入口）。
- 步骤：任意界面（非输入框）按下绑定快捷键。
- 预期：打开代码片段管理器 → 菜单打开（已打开则先关再开）；重新加载界面 → 执行重载（未保存编辑对话框二次确认逻辑同 MT-094）。编辑对话框内按快捷键不触发命令（编辑器拦截）。

### MT-195 输入框内按键不被吞
- 步骤：菜单搜索框、设置文本输入框、标题输入框、编辑区中按方向键/回车/Esc/常规键。
- 预期：文本输入与光标移动正常；编辑区内 Esc = 编辑对话框取消流程、Ctrl+F = CodeMirror 搜索（见 MT-054）；搜索框聚焦时按键不参与菜单导航（见 MT-190）；无按键“失效”或误触发菜单动作的明显异常。

## 14. 通知、自动重载与配置热应用细节

### MT-200 「不再提示」持久化
- 前置：触发条件（JS 修改提示）可复现。
- 步骤：触发一次「修改 JS 代码片段后需重新加载界面…」通知 → 点击通知内「不再提示」。
- 预期：
  - 通知关闭，且**此后不再弹出**该通知（配置 `通知：修改 JS 代码片段` 落盘为关）；
  - 呼吸/自动重载仍按原规则工作（提示只是不显示）；
  - 设置中把该项重新打开 → 通知恢复。

### MT-201 自动重载前置条件矩阵
- 步骤：结合「编辑对话框是否打开」「配置开关」两维重复 JS 修改保存。
- 预期矩阵（保存 JS 内容/禁用 JS 后）：
  | 自动重载配置 | 有未保存变更的编辑对话框开着 | 预期 |
  |---|---|---|
  | 开 | 无 | 保存/关闭菜单后自动重载 |
  | 开 | 有（且有未保存变更） | 不重载（避免丢内容）；关闭全部编辑对话框后再重载 |
  | 关 | 无 | 不重载，需手动点重载按钮 |
- 其中「关闭菜单」与「保存对话框」为两个自动重载触发点，可分别验证。

### MT-202 配置写入失败路径（只读场景模拟，可选）
- 说明：在正常桌面端难以模拟；可通过把 `data/storage/petal/snippets/` 设为只读（改回前勿保存）后尝试保存设置。
- 预期：保存失败弹「保存配置失败 [code: msg]」且**对话框保持打开**，可取消或重试；不出现对话框已关但配置未落盘的不一致。

### MT-203 打开菜单时 tooltip
- 前置：桌面端，顶栏按钮存在。
- 步骤：悬停顶栏按钮 → 出现 tooltip（标题 + 快捷键提示）；点击打开菜单期间悬停另一处再移回。
- 预期：菜单打开时按钮 tooltip 隐藏、按钮高亮；菜单关闭后 aria-label/tooltip 恢复。

## 15. 移动端冒烟（可选，需移动端/浏览器 UA 切换；模块差异点）

### MT-210 移动端菜单
- 步骤：移动端点击插件入口。

- 步骤：打开片段编辑对话框；打开一个后再尝试打开第二个。

## 17. 探索 / 易出问题场景（已知复杂，出现异常时记录上报）
